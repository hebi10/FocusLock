# UI-R02 — 온보딩 리디자인

기준: Google Drive [전체 화면 디자인 설계 v1.0](https://docs.google.com/document/d/160M4wHLgML5FHsKuORsU73akWD5ktMAAQp6nRbLW4W4/edit), D01 · UI-R00 기준 캡처 37장 · UI-R01 공통 토큰.
대상: `com.haebi.focuslock` (Kotlin / Jetpack Compose).
상태: PR 변경 및 자동 검증 대상. 최종 병합·Play 배포는 CI와 시각 검수 결과에 따라 판단.

## 구조 결정 — 3단계 유지

기획 D01은 소개 → 권한 → 관리 앱 선택 → 첫 목표의 4단계입니다. 그러나 실제 Android 최초 실행에서는 사용 통계 권한을 허용한 직후에도 사용 기록이 없을 수 있습니다. 빈 관리 앱 선택 화면을 별도 단계로 강제하지 않도록 **관리 앱 선택과 첫 목표를 마지막 단계로 묶은 3단계**를 유지합니다.

1. 소개: 기존 정원 그림을 작은 보조 요소로 사용하고 서비스 가치와 3개 기능 안내를 정돈. '시작하기' / '둘러보기' 유지.
2. 권한: 사용 정보 접근의 목적, Android 설정 이동, 목표 경고용 별도 알림 권한, 권한 없이 이용할 수 있는 집중·정원 안내. 실제 AppOps 허용 상태는 Android 설정 복귀 시 재조회. '나중에' 허용.
3. 첫 목표: 사용 기록 있음 → **오늘 사용 앱**, 없으면 **최근 7일 실제 앱 기록** 최대 5개. 앱별 '목표 설정'은 기존 GoalSheet/저장 경로를 그대로 사용. 미허용·로딩·조회 오류·기록 없음 상태를 구분하고 재확인/권한 설정 CTA 제공. 'FocusLock 시작' / '나중에 설정'으로 홈 진입 가능.

목표가 없는 앱을 임의 생성하지 않습니다. 사용 기록과 앱 목록은 Android UsageStatsManager 조회 결과에만 의존합니다. 기획의 설치 앱 전체 검색·복수 선택은 현재 Android 앱 가시성과 데이터 정책에 대한 별도 검토 없이 추가하지 않습니다.

## UI 구현 기준

- UI-R01의 라이트/다크 색상, 타이포, 간격 토큰을 재사용하고 새로운 그림자·그라데이션·애니메이션을 추가하지 않습니다.
- 상단 1/3·2/3·3/3 단계 표시와 얇은 진행 바로 현재 위치를 구분합니다.
- 제목·설명과 카드 영역은 스크롤, 하단 주 CTA 및 건너뛰기는 고정하여 작은 화면에서도 조작 가능하도록 합니다.
- 콘텐츠 가로 너비 최대 600dp, 일반 좌우 여백 16dp, 액션 52dp, 터치 영역 최소 48dp.
- 기존 화면의 '둘러보기', '나중에', 'FocusLock 시작' 동작과 SharedPreferences `onboarding_completed` 저장을 유지합니다.
- 권한 허용은 시스템 설정으로만 유도하며 강제 차단, 자동 앱 종료, 가짜 권한·사용 통계 수치를 표시하지 않습니다.

- Android CI: Kotlin 컴파일·단위 테스트·Lint·APK 빌드 성공.
- API36 에뮬레이터: 기존 UI-R00 스크린샷 37장 누락 없이 유지, 권한 거부 및 허용 상태 검증.
